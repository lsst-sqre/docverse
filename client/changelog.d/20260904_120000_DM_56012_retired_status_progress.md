### New features

- `BuildProcessingProgress` gains a `retired_status` field, typed by a new `RetiredBuildStatus` enum exported from `docverse.models`. It names the state a build was found in when its worker stood down — `cancelled` for a delete or lifecycle reap, `failed` for the stranded-build sweep, `superseded` for a newer build taking over, and `missing` when the row was gone by the time the worker looked. The key already round-tripped through `extra="allow"`, but only for statuses that exist: the vanished-row case wrote `null`, which the model's drop-`None` serializer stripped, leaving that outcome unrepresentable. Declaring the field puts the value in the generated OpenAPI schema as an enum callers can switch on, and the vanished-row close-out now serialises `retired_status: "missing"`. `RetiredBuildStatus` is `BuildStatus` plus `missing`, because a soft-deleted build keeps whatever status it had — `missing` is not a `BuildStatus` since there is no row to persist it on.
