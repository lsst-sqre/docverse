### New features

- `BuildCreate.content_hash` is now optional and deprecated, and `DocverseClient.create_build`'s `content_hash` argument defaults to `None` — when unset the key is left out of the request body rather than sent as `null`. Docverse now computes a build's content identity itself while processing the upload and overwrites whatever the client supplied, so the field is documented as a transport-integrity and provenance digest of the uploaded tarball that makes no claim about content identity, and it will be removed in a future release. Nothing breaks today: the `sha256:<64 hex>` pattern is still enforced on any value that is supplied, and `docverse upload` still computes the tarball digest with `create_tarball` and sends it. There is no runtime deprecation warning — the field descriptions, which surface in the server's OpenAPI schema, carry the notice.
