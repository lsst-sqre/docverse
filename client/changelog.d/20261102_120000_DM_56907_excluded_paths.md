### Backwards-incompatible changes

- `create_tarball` now returns a `Tarball` named tuple of `(path, content_hash, excluded_count, file_count)` instead of a `(path, content_hash)` pair, so code that unpacks the result into two names must switch to the attributes (`result.path`, `result.content_hash`). `Tarball` is exported from `docverse`.
- `docverse upload` now refuses, with a non-zero exit and before making any API call, a directory that contains no files once excluded cache paths are left out. That covers a directory holding only `.doctrees/` and the like, and an empty directory, which previously produced a build with no objects. There is no flag to override the refusal.

### New features

- New public module `docverse.excluded_paths` holds the canonical list of path names that Docverse never ingests into a build. `EXCLUDED_PATH_NAMES` is a frozenset of exactly `.doctrees`, `.buildinfo`, `.git`, `__pycache__`, `.pytest_cache`, `.ipynb_checkpoints`, `.DS_Store`, `Thumbs.db`, `.hg` and `.svn`, and `is_excluded_path(relative_path)` returns `True` when any `/`-separated segment of a build-relative path equals one of those names. Matching is exact and case-sensitive, with no globbing, and a leading `./` gives the same answer as the bare path. Both names are also re-exported from `docverse`. The list is fixed in code, and the Docverse server applies the same predicate wherever it ingests build content.
- `docverse upload` (via `create_tarball`) leaves excluded paths out of the tarball, so Sphinx build caches such as `.doctrees/` and `.buildinfo` are no longer uploaded and no longer affect the reported content hash. An excluded directory is not traversed. The command prints `Excluded N cache paths` when it leaves anything out, counting each excluded directory once.
