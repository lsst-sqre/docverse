### Backwards-incompatible changes

- `KeeperSyncConfig` no longer rejects unknown fields: it is a read model — it parses both the stored config blob and a server's response body — so an unknown key is now ignored rather than raising a `ValidationError`. This is what lets an older reader survive a field a newer server wrote, whether that reader is a rolled-back server loading the row or a published client parsing a `PATCH` response whose write has already applied. Code relying on `KeeperSyncConfig` to reject a misspelled field should validate through `KeeperSyncConfigWrite` instead.

### New features

- New `KeeperSyncConfigWrite` model: the request body of `PUT /orgs/{org}/keeper-sync`. It carries and validates exactly the fields of `KeeperSyncConfig` but keeps `extra="forbid"`, so a misspelled field in a request body is still rejected instead of being silently dropped. `KeeperSyncConfigUpdate`, the `PATCH` body, is unchanged and still forbids unknown fields.
