### New features

- `KeeperSyncConfig` gains three scope fields alongside the unchanged `project_slugs`: `project_slug_patterns` (regular expressions that add LTD slugs to scope), `exclude_project_slugs` (exact slugs removed from scope) and `exclude_project_slug_patterns` (regular expressions that remove slugs from scope). All three default to `[]`, so a config stored before this release loads unchanged, and `KeeperSyncConfigUpdate` carries a matching optional field for each — provided wholesale, like `project_slugs`, with an explicit `null` rejected.
- The keeper-sync scope rule is now defined once, on the model: `KeeperSyncConfig.is_in_scope(slug)` and `KeeperSyncConfig.filter_in_scope(slugs)` (order-preserving) resolve the included slugs — everything when `project_slugs` is `"*"`, otherwise the listed slugs plus the include-pattern matches — and then subtract the excludes, which always win. Patterns are Python regular expressions matched with `re.fullmatch` and are case-sensitive, so `sqr-1` matches `sqr-1` only, never `sqr-10` or `sqr-100`.
- Both models validate the pattern fields, so `PUT` and `PATCH` share one rule: every pattern must compile, a pattern field accepts at most 100 entries, and each pattern is capped at 256 characters. A rejected pattern's message names both the field and the offending pattern.
