### Bug fixes

- Turning `edition_autocreation.semver_aggregates` back on now backfills the aggregates it had suppressed. A keeper-sync poll that ran with the knob off still stamped its `aggregates_backfilled_build_id` convergence marker on the edition's `keeper_sync_state` row, even though creation had been declined and no `N` / `N.M` row existed to reconcile. Because `sync_build` hands back the same Docverse build id on every short-circuited poll, the marker matched forever: re-enabling the knob had no effect until LTD happened to publish a new build for that edition. The marker is now written only by a pass that actually reconciled something — creation allowed, or an existing aggregate advanced — so a suppressed edition stays unmarked and heals on the very next poll. Projects with the knob off pay one cheap re-decision per release edition per poll (a version parse plus a `get_by_slug` per aggregate slug); the steady-state skip for projects with it on is unchanged.
- A `v/`-prefix republish that lands mid-import is no longer permanently absorbed on LTD editions with no rebuild timestamp. When the prefix `sync_build` hashed changes before the copy reads it, the build's `date_rebuilt_seen` marker is retracted so the next poll re-resolves rather than short-circuiting on a resolution that never held — but `LtdEdition.date_rebuilt` is nullable, and null is the norm for LTD's oldest editions, which are exactly the ones whose un-ACL'd build uploads force the mutable `v/` fallback in the first place. For those, the retracted `NULL` marker compared equal to LTD's `NULL` timestamp, the next poll read "already converged", and the edition went on serving content copied from a prefix state that no longer exists. The retraction is now recorded explicitly as a `date_rebuilt_seen_retracted` annotation on the build's state row, so the short-circuit distinguishes a cleared marker from a matching one; it clears on the next clean resolve, and short-circuiting on a non-null marker that matches is unchanged.
