### New features

- `GET /orgs/{org}/projects` accepts an `updated_since` query parameter: a timezone-aware ISO 8601 timestamp that keeps only projects whose `date_updated` is at or after it, so a consumer polling the listing can ask for just what changed since its last pass. The bound is inclusive — handing back the newest timestamp of the previous page can never skip a project written in that same microsecond — and it applies to the fuzzy-search path (`q=`) as well as the ordered listing. A naive timestamp names an ambiguous instant and is rejected with a 422.
- The listing's `order` parameter accepts `date_updated`, which returns the most-recently-touched projects first (`id` as the tiebreak) and pages in both directions through the `Link` header like the other orderings.
- A new Alembic revision (`b9c0d1e2f3a4`) adds an `idx_projects_org_date_updated` index on `projects (org_id, date_updated, id)`, so an `updated_since` poll or a `date_updated` page is an index range scan rather than a sort over the organization's whole project set.
