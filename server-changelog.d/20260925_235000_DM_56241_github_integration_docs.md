### Other changes

- `docs/github-integration.md` is a new operations page for the GitHub App integration. It covers what each webhook delivery does, event by event: `push`, `delete`, `repository` `renamed` / `transferred` / `edited`, `organization` `renamed`, and the `installation` and `installation_repositories` actions. It covers how a project's `__main` edition follows its repository's default branch through three triggers (the `repository.edited` webhook, `project_github_resolve`, and the daily `git_ref_audit`), and the one guarded rule they share: record `github.default_branch`, rewrite `__main` only when its ref is gone, retire the duplicate draft, and repoint. It also lists what that rule never touches, how `lsst_doc` editions read the default branch, the audit as the post-upgrade backfill and the `git_ref_audit_enabled` flag it runs behind, how keeper-sync keeps synced projects converged, the GitHub settings with their environment variables and Phalanx values, every log line and field the default-branch convergence writes, and the manual `PATCH .../editions/__main` for a `__main` the rule leaves pinned. It is linked from `docs/index.md` and from the `github_webhook_received` section of `docs/metrics.md`. `tests/docs_test.py` fails when the page's webhook table stops matching the event router, or when its settings table, triggers, log-line table, log-field table, keeper-sync log line, or the edition endpoints it quotes stop matching the code.
