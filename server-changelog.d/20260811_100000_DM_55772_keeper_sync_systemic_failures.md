### Bug fixes

- A systemic outage part-way through a keeper-sync project no longer reports as a clean import. `sync_project` gives every edition its own failure boundary so one permanently-unreadable LTD build (an old upload carrying no public-read object ACL) costs one edition rather than every edition queued behind it, but that boundary made no distinction between an isolated fault and a shared one: an LTD outage or a database failure mid-run marked each remaining edition failed in turn, the loop ran to the end, and the project's queue job finished `completed` with its parent run rolled up green — a 3-of-80 import presenting as a completed run. Two changes close that gap. A run of five *consecutive* edition failures is now read as systemic rather than per-edition and raises `KeeperSyncSystemicFailureError` (chained from the triggering error) out of `sync_project`, so the worker fails the queue job instead of walking the rest of the edition list; any single success resets the counter, leaving scattered isolated failures with the per-edition isolation they need. And a project sync that does reach the end of its edition list with any isolated failure now completes `completed_with_errors` rather than plain `completed`, matching the `git_ref_audit` worker's `complete(has_errors=...)` signal. The run rollup needs no new status: `KeeperSyncRunStore.aggregate_activity` already buckets `completed_with_errors` as a failure, so the parent run finalises `partial_failure`.

- A failing semver-aggregate backfill no longer discards a successful edition sync. The `N` / `N.M` aggregate backfill runs after `sync_build` has committed the build row and repointed the edition, so the edition's content and pointer are already durable by the time it runs; letting its exception escape handed the whole edition to `sync_project`'s per-edition boundary, which recorded it as an `EditionSyncFailure` and emitted no `EditionSyncOutcome`. That suppressed the `on_edition_synced` publish enqueue and put the edition out of reach of the tail-end self-heal pass, which iterates only the outcomes — a fully-imported edition was reported failed and its CDN pointer never published for that run. A backfill failure is now captured to Sentry and logged with the edition's LTD and Docverse identity, and the edition still returns its successful outcome with no aggregates attached.
