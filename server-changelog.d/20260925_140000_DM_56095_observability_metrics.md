### New features

- Four metrics-event changes let the Chronograf dashboards answer how long an LTD Keeper rebuild takes to reach Docverse, how many API requests Docverse serves per route, how fast it answers them, and what becomes of each GitHub webhook delivery. Two existing events gain a nullable field each, and neither new event derives from the shared payload base: `api_request` carries `organization` and `project` as optional fields, and `github_webhook_received` carries neither. No other event schema changes.
  - `edition_published` gains `ltd_lag`: the publish's success time minus the `date_rebuilt` LTD Keeper reported for the edition. It is set when a keeper-sync visit imported a fresh LTD rebuild of an edition Docverse already mirrors (semver aggregates the same visit moved report their release's lag), and null on an edition's first import (whose `date_rebuilt` dates a rebuild from before the mirror, often years old on a backfill), for build fan-out, rollback, reconcile, and keeper-sync self-heal publishes, for LTD editions with no `date_rebuilt`, and for `publish_edition` jobs enqueued before this release. Negative values from clock skew are reported as they are, not clamped. The `publish_edition` job payload carries the rebuild time under a new optional `ltd_date_rebuilt` key.
  - `build_content_copied` gains `ltd_lag_seconds`: the copy's end minus the same `date_rebuilt`, in float seconds, which is the copy half of `ltd_lag`. It is set for the same copies, so it is null on an edition's first import too.
  - New `api_request` event, published by a new ASGI middleware once per API response except `GET /` and `GET /health`: `method` (one of RFC 9110's nine methods, or `OTHER` for any other token, so a scanner cannot mint new tag values), the matched route template with the path prefix removed (`route`, null when no route matched), `status_code`, `status_class` (`1xx` to `5xx`), `duration`, `authenticated` (whether Gafaelfawr set `X-Auth-Request-User`), and the `organization` and `project` path parameters. It never carries the concrete path or the username. An exception that escapes the application before its response starts is recorded as a `500` and re-raised; one that escapes after the response started (a streaming body that raises midway) keeps the status the caller already received, is re-raised, and is flagged by an `API response failed after it started` warning log line. A failed publish is logged and swallowed, so a metrics outage never changes a response.
  - New `github_webhook_received` event, published once per delivery to `POST {path_prefix}/webhooks/github`: `event_type` (from `X-GitHub-Event`, and only for a delivery whose signature verified), `outcome` (`dispatched`, `ignored`, `invalid_signature`, `malformed`, `not_configured`, or `error`), `jobs_enqueued`, `elapsed`, and `github_repository`. It has no `organization` or `project` field, because no delivery is resolved to either.
- Deployment needs a Phalanx change adding `method`, `route`, `status_class`, `authenticated`, `event_type`, and `outcome` to `globalAppConfig.docverse.influxTags` in the Sasquatch `app-metrics` chart values. Until it is synced those six are written as InfluxDB fields rather than tags. Because the tag list applies to every Docverse measurement, `outcome` also becomes a tag on the existing `conditional_get` event.

### Bug fixes

- A signed GitHub webhook delivery that gidgethub cannot parse (a content type other than JSON or a form, a body that does not decode, or a missing `X-GitHub-Event` or `X-GitHub-Delivery` header) is now answered `400 Bad Request` and recorded as `outcome=malformed`, instead of raising out of the handler as a `500`. `error` is left for failures while dispatching a delivery, so an alert on it is not set off by a caller's mistake. gidgethub checks the signature before parsing, so an unsigned request of any shape is still `401` and `invalid_signature`.

- An LTD Keeper timestamp that arrives without a UTC offset (`date_created`, `date_rebuilt`, or `date_ended` on an edition or build) is now read as UTC, so it compares against Docverse's clocks instead of failing the edition's sync with a `TypeError`.

### Other changes

- `docs/metrics.md` is a new catalog of every Sasquatch event Docverse publishes: its InfluxDB measurement (`lsst.square.metrics.events.docverse.<event>`), each field's type and meaning, which fields are tags under the Phalanx `influxTags` list and which events each tag applies to, the cardinality rule for choosing a tag, what `ltd_lag` and `ltd_lag_seconds` measure and when they are null, and example InfluxQL queries for sync lag, request volume, request latency, and webhook deliveries. It is linked from `docs/index.md`, from `build_content_copied` on the keeper-sync transport page, from the conditional GET section of the API conventions page, and from the README. `tests/docs_test.py` fails when an event `DocverseEvents.initialize` registers, or one of its fields, is missing from the page or typed or tagged differently there, and when the page documents a field an event does not carry.
