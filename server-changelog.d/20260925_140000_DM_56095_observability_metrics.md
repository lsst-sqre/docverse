### New features

- Four metrics-event changes let the Chronograf dashboards answer how long an LTD Keeper rebuild takes to reach Docverse, how many API requests Docverse serves per route, how fast it answers them, and what becomes of each GitHub webhook delivery. Two existing events gain a nullable field each, and the two new events carry `organization` and `project` as optional fields rather than deriving from the shared payload base; no other event schema changes.
  - `edition_published` gains `ltd_lag`: the publish's success time minus the `date_rebuilt` LTD Keeper reported for the edition. It is set when a keeper-sync visit imported a fresh LTD rebuild (semver aggregates the same visit moved report their release's lag), and null for build fan-out, rollback, reconcile, and keeper-sync self-heal publishes, for LTD editions with no `date_rebuilt`, and for `publish_edition` jobs enqueued before this release. Negative values from clock skew are reported as they are, not clamped. The `publish_edition` job payload carries the rebuild time under a new optional `ltd_date_rebuilt` key.
  - `build_content_copied` gains `ltd_lag_seconds`: the copy's end minus the same `date_rebuilt`, in float seconds, which is the copy half of `ltd_lag`.
  - New `api_request` event, published by a new ASGI middleware once per API response except `GET /` and `GET /health`: `method`, the matched route template with the path prefix removed (`route`, null when no route matched), `status_code`, `status_class` (`1xx` to `5xx`), `duration`, `authenticated` (whether Gafaelfawr set `X-Auth-Request-User`), and the `organization` and `project` path parameters. It never carries the concrete path or the username. An exception that escapes the application is recorded as a `500` and re-raised, and a failed publish is logged and swallowed, so a metrics outage never changes a response.
  - New `github_webhook_received` event, published once per delivery to `POST {path_prefix}/webhooks/github`: `event_type` (from `X-GitHub-Event`, and only for a delivery whose signature verified), `outcome` (`dispatched`, `ignored`, `invalid_signature`, `not_configured`, or `error`), `jobs_enqueued`, `elapsed`, and `github_repository`. `organization` and `project` are reserved and always null.
- Deployment needs a Phalanx change adding `method`, `route`, `status_class`, `authenticated`, `event_type`, and `outcome` to `globalAppConfig.docverse.influxTags` in the Sasquatch `app-metrics` chart values. Until it is synced those six are written as InfluxDB fields rather than tags. Because the tag list applies to every Docverse measurement, `outcome` also becomes a tag on the existing `conditional_get` event.

### Other changes

- `docs/metrics.md` is a new catalog of every Sasquatch event Docverse publishes: its InfluxDB measurement (`lsst.square.metrics.events.docverse.<event>`), each field's type and meaning, which fields are tags under the Phalanx `influxTags` list and which events each tag applies to, the cardinality rule for choosing a tag, what `ltd_lag` and `ltd_lag_seconds` measure and when they are null, and example InfluxQL queries for sync lag, request volume, request latency, and webhook deliveries. It is linked from `docs/index.md`, from `build_content_copied` on the keeper-sync transport page, from the conditional GET section of the API conventions page, and from the README. `tests/docs_test.py` fails when an event `DocverseEvents.initialize` registers, or one of its fields, is missing from the page or typed or tagged differently there.
