### Bug fixes

- Keeper-sync now realigns an edition's tracking columns and recomputes its kind even when its own insert loses a slug race. `_ensure_edition` reads the edition by slug and, on a miss, inserts with `ON CONFLICT DO NOTHING`; a concurrent writer (typically the native build-upload path handling an upload for the same ref) that landed the same `(project, slug)` row in that window wins the conflict and its row is handed back instead. That row was previously returned verbatim, so the sync reported it without applying the tracking refresh or the promote-only `draft` → `release` recompute PRD #498 promises on every sync — leaving it stale until a later sync happened to find it by slug. Both refreshes now run after every insert; on a genuinely fresh row they are no-ops, because it already carries the requested tracking params and the promote-only kind rule never rewrites a kind to itself.
