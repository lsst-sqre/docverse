### Bug fixes

- CDN cache purges for one project are now coalesced across a publish burst instead of firing once per edition. Purging is hostname-scoped — the only mechanism available on every Cloudflare plan tier — so every edition of a project emits a byte-identical purge call: publishing one release fans out into a purge for the release plus one for each semver aggregate edition, and a bulk keeper-sync backfill turns a project's release history into hundreds of redundant identical calls, which is what pushed the purge endpoint past its rate limit in the first place. Each worker process now folds those requests through a per-hostname coalescer that runs at most one purge at a time and spaces successive purges by `DOCVERSE_CDN_PURGE_MIN_INTERVAL_SECONDS` (default 2 s), so requests arriving while a purge is pending are absorbed by it. Coalescing never drops the trailing purge: the outstanding-request count is snapshotted immediately before the purge fires, so a request registered after that snapshot is deliberately left uncovered and gets its own purge — every publish is still followed by a purge that started after it, and the edge cannot be left holding stale content. An isolated publish waits for nothing, because only a purge that follows a recent one is throttled; a failed purge does not mark the burst served either, so the next waiter re-attempts rather than inheriting the failure. Editions on the short cache profile continue to skip purging entirely.
