### New features

- The concurrency knobs that set the worker pools' memory ceilings are now configuration rather than literals. `DOCVERSE_KEEPER_SYNC_COPY_CONCURRENCY` (default 8) sets the fan-out bound `BuildContentCopier` runs one LTD build prefix through, replacing a hardcoded `8` in `factory.py` that duplicated the copier's own default and that neither call site could override. `DOCVERSE_ARQ_MAX_JOBS`, `DOCVERSE_KEEPER_SYNC_MAX_JOBS`, and `DOCVERSE_MAINTENANCE_MAX_JOBS` (all default 10) set `max_jobs` explicitly on the default, keeper-sync, and maintenance `WorkerSettings`, which had all been silently inheriting arq's implicit default. The sync worker's real memory bound is the product of two of these — `keeper_sync_max_jobs` x `keeper_sync_copy_concurrency`, or 80 concurrently buffered object bodies at stock settings — because each concurrent `keeper_sync_project` job drives its own copier pool. That product is what the sync worker's memory limit is sized against, and until now no operator knob could move either factor, so the sizing held only as long as both literals stayed where they were. Defaults preserve current behaviour exactly; the relationship is documented on the config fields and on `KeeperSyncWorkerSettings`, so raising either knob visibly requires raising the pod's memory limit with it.
