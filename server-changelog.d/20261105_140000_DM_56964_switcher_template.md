### New features

- A dashboard template set can now render its own version switcher. The optional `[switcher] template` key in `template.toml` names a Jinja file that renders `__switcher.json` with the same variables as the dashboard page (`org`, `project`, `editions`, `assets`, `docverse`, `rendered_at`); `include_kinds` is ignored when it is set. The output must be a JSON array of objects with string `name`, `version` and `url`, an optional boolean `preferred`, and no other keys, and it is re-serialized in the built-in switcher's format. Any other output raises `InvalidSwitcherJsonError`, which fails the `dashboard_build` job the way a broken dashboard template does: a Sentry event, the error in the job's `errors`, and nothing uploaded. A set without the key renders `__switcher.json` exactly as before.
- New reference page, `docs/dashboard-templates.md`, documents template-set bindings, every `template.toml` key and its default, the variables each Jinja file renders with, and the switcher-template contract.
