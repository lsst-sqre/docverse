### Bug fixes

- The native build-upload path now honors a slug-rewrite rule that declares semver tags non-releases when deciding whether to auto-create semver aggregate editions. Keeper-sync's aggregate backfill already gated on the rule-derived kind — an org rule such as `{"type": "semver", "edition_kind": "draft"}` means "these refs are not releases here" and suppressed the `1` / `1.2` rows on import — but `EditionTrackingService` consulted only the semver grammar and the `edition_autocreation.semver_aggregates` knob, so a native upload of `1.2.3` still created the aggregates that an equivalent keeper-sync import refused to. The two paths are required to produce identical rows, or a migrated project renders different dashboard groups from a natively built one; the kind derived in the edition-slug step is now threaded through to the aggregate step and gates it on the same `release` test keeper-sync uses. Projects with no such rule are unaffected: the built-in `semver` heuristic classifies stable tags as releases, so the aggregates are created exactly as before. The `edition_autocreation` opt-out still gates creation only — an aggregate edition that already exists keeps tracking new releases either way.
