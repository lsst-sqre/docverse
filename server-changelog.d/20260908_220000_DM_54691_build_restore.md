### New features

- `POST /orgs/{org}/projects/{project}/builds/{build}/restore` undoes a build DELETE while the build's object-store content is still there, returning the revived build with `200`. It carries the same admin-only authorization as the DELETE it reverses. A restored build rejoins the ordinary build listing and is a valid rollback target again; its status is deliberately untouched, so a build cancelled on its way out comes back `cancelled` — the endpoint returns the row and its content, not a re-run. A build whose `date_purged` is set answers `409`, because the `purgatory_cleanup` sweep has permanently reclaimed its tree and tarball and no row edit brings those back, and a build that was never deleted answers `404`.

### Other changes

- `DELETE /orgs/{org}/projects/{project}/builds/{build}` now documents its `409` response in the OpenAPI schema. The refusal for a build a live edition is still serving already existed; only the contract was missing it.
