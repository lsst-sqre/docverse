### Other changes

- Docverse now records why each edition was soft-deleted. A new nullable `editions.delete_reason` column (alembic revision `d1e2f3a4b5c6`), constrained to `manual_delete` or `lifecycle_delete`, is stamped in the same flush as `date_deleted` by a per-edition delete (from the delete's tombstone reason) and by a project delete's cascade (with the project's reason), and is cleared when a keeper-sync tombstone clear revives the edition. The migration backfills existing soft-deleted editions from the tombstone on their `keeper_sync_state` row, most recent tombstone first, folding `lifecycle_preemptive` into `lifecycle_delete`; a soft-deleted edition with no tombstone to copy from stays `NULL`, which later consumers read as revivable. Native editions have no keeper-sync state row, so this is the only record of their deletion's provenance. The column is server-side only and does not appear on the edition API resource. This is the first step toward reviving lifecycle-deleted editions on new activity (PRD #830); nothing reads the column yet.
