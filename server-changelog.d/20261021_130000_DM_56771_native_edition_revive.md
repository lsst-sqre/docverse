### Bug fixes

- A client build for a git ref whose edition a lifecycle rule had soft-deleted no longer fails edition tracking. The soft-deleted edition kept its slug, so auto-creating the edition again raised "create_internal lost ON CONFLICT race" and captured it to Sentry on every build for that ref, and the build tracked no edition. Edition tracking now revives the edition in place when it was deleted by a lifecycle rule (`editions.delete_reason` of `lifecycle_delete`, or no recorded reason): it keeps its id, title, `lifecycle_exempt`, alternate name, and build history, takes the current derivation's tracking (and its kind, unless an operator declared one), clears any keeper-sync tombstone on the edition, and advances to the new build like a newly created edition, so the build is published and the project's dashboard rebuilt. Semver aggregate editions (`N` / `N.M`) revive the same way, but only from a soft-deleted row already on the aggregate's own tracking mode (`semver_major` / `semver_minor`): an edition on any other tracking mode holding the slug, such as one an operator made to follow git ref `2`, stays deleted and the release skips that aggregate, as it does when a live edition of another tracking mode holds the slug. An edition an operator deleted stays deleted: the build is stored, no edition is tracked, and the worker logs the warning "Edition slug reserved by manual delete; build not tracked" instead of reporting an error. Each revived edition publishes one `edition_lifecycle` metrics event with the new `restore` action.
