### New features

- Dashboard and switcher templates can now pick an edition by slug: `editions.by_slug` maps every live edition, `__main` included, to the same object the grouped lists hold (`editions.by_slug['weekly']`).
- `editions.releases` now orders EUPS release slugs by version. A slug is read as semver first, then as an EUPS release tag, so `v30_0_12`, `v30_0_11`, `v17_0_1`, `v17_0` and the legacy `13-0` list newest first rather than in slug order, with a release candidate below its final release. Slugs neither grammar reads still sort last, and semver-slugged projects order exactly as before.
- The built-in `__switcher.json` now orders EUPS release tags by their full version too, rather than by their major alone, so it lists `v30_0_12` above `v30_0_12_rc3` and `v30_0_11` whatever order the editions arrive in.

### Bug fixes

- `editions.releases` now orders two-component lsst_doc release slugs (`v1.2`, `v1.10`, `v2.0`) newest version first, as the dashboard template docs describe. These slugs are not semver, so they previously sorted as unparseable and kept slug order (`v1.10`, `v1.2`, `v2.0`); the EUPS grammar's dotted two-component form now reads them, which changes the release order on the `/v/` dashboard of every project with such slugs, including migrated technotes.
