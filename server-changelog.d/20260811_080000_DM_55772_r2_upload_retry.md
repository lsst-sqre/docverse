### Bug fixes

- Object uploads to Cloudflare R2 are now retried instead of killing the copy that was using them. `S3ObjectStore.upload_object` has two branches, and the one production takes — a presigned PUT over the shared `httpx` client — had no retry at all: a single R2 `500` or a bare `ReadTimeout` raised straight out through `BuildContentCopier.copy_build` and aborted a keeper-sync project part-way, forcing a manual re-run that re-downloaded and re-uploaded everything already copied (a roundtable-dev backfill needed four such re-runs). The presigned PUT now retries the transient statuses (`429`, `500`, `502`, `503`, `504`) and the transport failures that produce no response at all (timeouts, connection errors, and a peer that hangs up mid-response) with bounded exponential backoff, honouring a numeric `Retry-After` when the destination sends one (capped at 10 seconds). Every other non-2xx — including an unfollowed 3xx redirect, which would otherwise report a build as copied when the object was never stored — still fails on the first attempt, because a retry cannot fix a malformed request or a signature the destination rejects. Retrying is safe because a PUT of the same key with the same bytes is idempotent, and each attempt mints a fresh presigned URL rather than replaying a signature that may have expired while the retries were backing off. An upload that exhausts its budget still raises, so callers keep the failure contract they had. The aiobotocore fallback branch is unchanged: it already inherits botocore's own retry behaviour.
