### New features

- `GET /orgs/{org}/projects` supports conditional GET. Every response carries a weak `ETag` derived from the organization's project watermark (its project count and the sum of every project's `date_updated`, soft-deleted rows included). A request that repeats a matching `If-None-Match` is answered with an empty `304 Not Modified` carrying that tag, and the listing query is never run — so a poll that finds nothing new costs one aggregate query instead of a serialized page. Each page and each filter combination gets its own `ETag`. The tag is the only validator: no `Last-Modified` is sent, and an `If-Modified-Since` is ignored rather than rejected, because a date can only name the maximum of the clocks behind the listing and that maximum is not monotonic under PostgreSQL's transaction-start clocks.

### Other changes

- A new `conditional_get` application metrics event records the endpoint, organization, outcome (`not_modified` / `modified`), and which header decided (`etag`) for every request that carried a precondition header, so the cache hit rate of a polling consumer is directly queryable. Unconditional requests emit nothing.
