### New features

- `GET /orgs/{org}/projects` supports conditional GET. Every response carries a weak `ETag` and a `Last-Modified` derived from the organization's project watermark (the newest `date_updated` among its projects, soft-deleted ones included, falling back to the org's own `date_created` when it has none). A request that repeats a matching `If-None-Match`, or an `If-Modified-Since` at or after the watermark, is answered with an empty `304 Not Modified` carrying both validators, and the listing query is never run — so a poll that finds nothing new costs one aggregate query instead of a serialized page. Per RFC 7232, `If-None-Match` is evaluated whenever it is present and `If-Modified-Since` is consulted only in its absence; an unparsable date is ignored rather than rejected. Each page and each filter combination gets its own `ETag`.

### Other changes

- A new `conditional_get` application metrics event records the endpoint, organization, outcome (`not_modified` / `modified`), and which header decided (`etag` / `last_modified`) for every request that carried a precondition header, so the cache hit rate of a polling consumer is directly queryable. Unconditional requests emit nothing.
