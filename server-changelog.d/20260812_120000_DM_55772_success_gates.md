### Bug fixes

- The last three HTTP success checks in the storage layer that counted a 3xx as success now require a 2xx, matching the presigned-PUT and cache-purge paths. `LtdClient._get_json` tested `response.is_error`, which is only true for 4xx/5xx, so an unfollowed redirect — nothing in this codebase builds an `httpx.AsyncClient` that follows them, so an SSO gateway or a moved endpoint in front of LTD returns a login page — fell through into `response.json()` and raised `json.JSONDecodeError`. That escaped the `LtdClientError` taxonomy every caller handles: it aborted the keeper-sync tier crons outright, and inside `sync_project` it burned an edition-failure slot toward the consecutive-failure abort. A 3xx now raises `LtdClientError` with the status code and truncated body, immediately and without retrying, exactly like any other non-retryable status. The Cloudflare Workers KV edition publisher gated its diagnostic on the same check in both `publish` and `unpublish`, so a redirect (the pointer was never written, or never removed) raised a bare `httpx.HTTPStatusError` with nothing logged for a triager to read; both now log the status code and response body for every non-2xx before raising. The 404-as-success no-op in `unpublish`, the 429/5xx retry paths, and the non-retryable 4xx behaviour are all unchanged.
