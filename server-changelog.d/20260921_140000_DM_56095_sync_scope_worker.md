### New features

- The keeper-sync worker now resolves its scope through the config model's shared rule, so a backfill run's discovery fan-out and all three tier crons honour `project_slug_patterns`, `exclude_project_slugs` and `exclude_project_slug_patterns` alongside `project_slugs`. A product that appears on LTD after the config was written joins the cadence as soon as an include pattern matches it, with no config change.
- Falling out of the keeper-sync scope is not a delete. A synced project that becomes excluded simply stops being enqueued; its Docverse project, editions, builds and keeper-sync state rows are left untouched and are never tombstoned, so bringing it back into scope resumes syncing.
- The `Resolved keeper-sync run scope` log event gains `excluded_count`, the number of LTD slugs an include rule admitted and an exclude rule then removed. Each tier-cron tick now logs its own scope resolution as `Resolved keeper-sync tier scope`, carrying the same `ltd_count`, `in_scope_count`, `excluded_count` and `tombstoned_count` alongside the org slug.
