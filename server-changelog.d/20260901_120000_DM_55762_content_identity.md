### Backwards-incompatible changes

- A completed build's `content_hash` is now the content identity Docverse computes for itself, not the digest the uploading client sent. The column had two producers hashing different things — the client hashed its gzipped tarball stream, keeper-sync's copier hashed a sorted per-file manifest — so the dual-upload convergence lookup could only ever match rows the copier had written, and content uploaded through the client could never be recognized as content Docverse already held. The build-processing worker now hashes each file as it extracts it and writes the same manifest digest the copier produces, landing it atomically with the transition to `completed` so a row is never observable as completed while still holding the pending value; the computed hash is included in the worker's `Upload complete` log event. Historical rows are deliberately not backfilled, so a build completed before this release keeps whatever its producer wrote and will not converge with an LTD sync of the same content until it is rebuilt. Any consumer comparing a completed build's `content_hash` against its own tarball digest will stop matching.

### New features

- `content_hash` is now optional on `POST /orgs/{org}/projects/{project}/builds`, and the request field is deprecated. It never described a build's content, only the bytes on the wire, and now that the server computes content identity itself the field is documented as a transport-integrity and provenance digest that makes no identity claim. Omitting it leaves the pending row holding a placeholder (`sha256:` followed by 64 zeros) until the worker writes the real identity at completion. Clients that still send it are unaffected: the value is stored on the pending row as before, the `sha256:<64 hex>` pattern is still enforced on anything supplied, and there is no runtime deprecation warning — the notice lives in the OpenAPI field descriptions, where the `Build` response's `content_hash` now also spells out which of the two meanings applies at which status.
