### New features

- Added the store queries and service the `purgatory_cleanup` sweep runs on. `BuildStore.list_purgeable` returns one organization's soft-deleted, not-yet-reclaimed builds whose deletion predates the org's retention window, oldest deletion first and capped — the ordering is what lets a capped tick resume where the last one stopped. It deliberately reaches builds of soft-deleted projects, which is how a deleted project's storage ages into purgatory instead of staying pinned to the store. `BuildStore.mark_purged` stamps `date_purged` conditionally, in the same statement that checks the row is still deleted and unstamped, so a restore that lands between the reclaim and the stamp is reported rather than overwritten. `BuildStore.list_org_ids_with_purgeable_builds` is the dispatcher's pre-flight, adding each organization's own retention to each build's deletion instant so an org with a ninety-day window is not swept on a neighbour's one-day cutoff.
- Added `PurgatoryService`, whose two entry points are session-free so the worker owns every transaction. `plan` partitions an org's expired builds into the ones the sweep may take and the ones a live edition still serves — the latter carry the edition slugs, so an operator can see which edition to roll back — and `reclaim` deletes the build's tree and staging tarball and reports the object count and the size the row recorded. A store that refuses part of a delete raises out of `reclaim` rather than being counted as a purge, which is what keeps `date_purged` from being stamped over objects still on the store.

### Other changes

- Added the five `DOCVERSE_PURGATORY_CLEANUP_*` settings the sweep runs on: the `enabled` feature flag, a 500-build per-job cap with a floor of 1, the 03:23 UTC dispatcher cron slot, and a six-hour reaper threshold matching its siblings. The sweep ships **disabled**: the flag is false by default, because the job deletes object-store content permanently, and it is turned on one environment at a time through Phalanx (`config.maintenance.purgatoryCleanupEnabled` in `applications/docverse`, alongside the cap, cron and threshold values). Until an environment sets it, the dispatcher's nightly tick returns immediately and no organization is swept.
