### New features

- Keeper-sync now re-runs a build-content copy once when it fails on a transport error (an R2 connect timeout or a dropped connection that outlasted the per-object upload budget), instead of failing the edition straight away. The worker logs "Retrying build copy after transport error" with the error's `error_type` and `retry_delay`, waits `DOCVERSE_KEEPER_SYNC_COPY_RETRY_DELAY_SECONDS` (default 30.0, at least 0), and copies again into the same placeholder build. Copies are content-hashed and idempotent, and the wait holds no database transaction. A second failure, and any non-transport failure (an LTD `AccessDenied`, an S3 client error, an HTTP error status), still fails the edition as before.
