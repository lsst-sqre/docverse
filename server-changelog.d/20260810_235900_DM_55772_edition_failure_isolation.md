### Bug fixes

- Keeper-sync now gives each LTD edition its own failure boundary during a project sync. Previously one raising edition abandoned every remaining edition in the project, so a single permanently-unreadable LTD build (LTD's oldest uploads have no public-read object ACL, so anonymous reads of them return `AccessDenied`) stalled every release behind it, and a transient object-storage error meant re-running the whole product. Each failure is now captured to Sentry and logged with the LTD edition's slug and id, the remaining editions sync normally, and the skipped editions are recorded on the `keeper_sync_project` job's `progress` as `edition_failure_count` plus an `edition_failures` list (capped at 20 entries; the count is always exact). The job still finishes `completed` — a permanently-broken LTD build must not paint the project's sync red on every subsequent poll — so the per-edition failures are the partial-success signal. Only a whole-project failure (the LTD product fetch, the org lookup, the destination object store) still fails the job.
