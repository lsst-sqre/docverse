### Bug fixes

- `POST /orgs/{org}/keeper-sync/scope-preview` now answers 502 — not 500 — when LTD returns `200` with a body that is not a product listing, such as a proxy's HTML maintenance page or a bare JSON array. Only transport and status failures were mapped before, so a malformed body escaped as `json.JSONDecodeError` or `AttributeError` and contradicted the endpoint's documented "never a Docverse 500" contract. The 502's message names LTD's status (a `200` here being the useful surprise) and what could not be read.

### Other changes

- The LTD product listing is now fetched through one path for every caller: `LtdProductsClient.list_product_slugs` validates the payload shape and raises a single `LtdProductsError` (an `LtdClientError`) for a transport failure, a non-2xx status, a non-JSON or non-object body, a non-list `products` field, or an entry that is not a product URL. Each caller keeps its own error policy at its own call site — the scope-preview endpoint maps it to a 502 without alerting because an operator is watching the response, while the unattended keeper-sync run discovery and tier crons let it fail the pass and alert. A malformed listing is an error rather than an empty one, so an LTD outage can no longer present itself as "nothing in scope".
