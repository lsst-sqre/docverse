### New features

- `GET`, `PUT` and `PATCH /orgs/{org}/keeper-sync` now carry three scope fields beside `project_slugs`: `project_slug_patterns`, `exclude_project_slugs` and `exclude_project_slug_patterns`. `PATCH` merges each of them the way it already merges `project_slugs` — provided wholesale, omitted to leave unchanged, explicit `null` rejected — and an uncompilable pattern, an over-long pattern (the cap is 256 characters) or more than 100 patterns in one field is a 422 naming the field and the offending pattern. No database migration is needed: the config is JSONB and an organization configured before this release reads back with the three new fields empty.
- The `Updated keeper_sync_config` log event records the size of each of the four scope fields, as `project_slugs_count` (`null` for the `"*"` wildcard, which has no size), `project_slug_patterns_count`, `exclude_project_slugs_count` and `exclude_project_slug_patterns_count`.

### Other changes

- This release only stores and validates the new keeper-sync scope fields. The sync worker, the tier crons and the per-project keeper-sync endpoints still resolve scope from `project_slugs` alone; they move onto the model's shared scope rule in a follow-on release.
