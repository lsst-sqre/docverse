### Bug fixes

- The `Resolved keeper-sync run scope` and `Resolved keeper-sync tier scope` log events now use the scope preview's definitions for the field names they share with it, so a preview and the run it launches can actually be laid side by side. `in_scope_count` is the config resolution *before* tombstones are subtracted (it was reported after, while the preview's has always been before), and `tombstoned_count` counts only the tombstones inside that scope (it was the org's entire tombstone population, so a preview reporting `in_scope_count=3, tombstoned=1` could launch a run logging `in_scope_count=2, tombstoned_count=40`). Both events, and the discovery job's `queue_jobs.progress`, gained `fan_out_count` — the post-subtraction number that becomes the run's `total_count` — so the three counts now compose into the identity `in_scope_count - tombstoned_count = fan_out_count`. `ltd_count` and `excluded_count` are unchanged, and no fan-out behaviour changed.
