### New features

- Added `purgatory_cleanup_reaper`, the cron backstop for the nightly sweep, on the maintenance pool at minutes 21 and 51 — the last free pair on a pool where every other reaper already holds its own offset slot. It is the fifth kind on the shared run-less reaper, so it sweeps `purgatory_cleanup` queue jobs exactly as its siblings do: a row left `in_progress` past `DOCVERSE_PURGATORY_CLEANUP_REAPER_THRESHOLD_SECONDS` (six hours by default) by a worker that died mid-sweep, a `queued` row a crashed dispatcher never enqueued, and a `queued` row arq itself lost, each verified against the queue backend before it is failed. Without it a single stuck row would hold that organization's per-org mutex forever, so every following nightly tick would step over the org and its expired builds would keep their object-store content indefinitely — the exact cost the sweep exists to remove.
