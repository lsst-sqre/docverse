### Bug fixes

- Repointing an edition at the build it already serves is now a no-op. `PATCH /orgs/{org}/projects/{project}/editions/{edition}` with a `build` that is already current, and `POST .../rollback` to the build already being served, both answer `200` with the unchanged edition — and record no `edition_build_history` row, flip no `publish_status`, and enqueue no `publish_edition` job. Both paths waive the stale-build guard, which is what used to refuse a build compared against itself, so once a `__main` repoint began advancing `projects.date_updated` each of these re-requests retired the project's cached `ETag` and re-emitted a byte-identical row into every consumer's `updated_since` window. An operator retrying a rollback after a dropped connection now costs nothing.
- A rollback naming a build outside the edition's history is still a `404`; the membership check runs before the no-op case, because an emergency `build` override can leave an edition serving a build that rollback was never offered. Repointing to any *different* build still takes the full path: it advances the project clock, records history, and enqueues the publish.
