### Bug fixes

- A project that explicitly sets `slug_rewrite_rules` to `[]` now genuinely opts out of its organization's rules instead of silently inheriting them. Both resolution sites — keeper-sync and the native edition-tracking path — previously fell back to the org's rules whenever the project's list was falsy, so an empty list was indistinguishable from an unset one: refs the org ignored were still suppressed (and tombstoned on the keeper-sync preemptive pass), and org-level kind overrides still classified the project's editions. Resolution now keys on `None` (never set) rather than falsiness, per the SQR-112 inheritance rule that a project's rule list replaces the org's whole-object when set. A project with `[]` is governed only by the built-in version heuristics; `null` still inherits the org's rules, and a non-empty project list still replaces them entirely.
