### Bug fixes

- The reapers' postmortem log payloads now spell queue-job ids the way the rest of the server does. `reaped_jobs` (emitted by the four run-less reapers, `keeper_sync_reaper`, and `lifecycle_reaper`) and the run-less reapers' `reaped_public_ids` logged `public_id` as the raw integer behind the base32 identifier — the base32 serializer only fires in Pydantic JSON output, not in a structlog call — so the id an operator arrives with, from the jobs API or from a `Skipping late-delivered queue job` warning, matched nothing in the reaper's own logs and the cross-reference those payloads exist for came back empty. Both fields now carry the hyphenated base32 public id, and the builder behind them lives in one place instead of being pasted into all three reaper modules, so the three cannot drift apart in the field an operator greps.
