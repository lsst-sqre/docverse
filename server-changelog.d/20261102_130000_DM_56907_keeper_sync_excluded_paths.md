### New features

- Keeper-sync no longer imports build caches that LTD published beside a build's HTML. Before downloading anything, the copier drops every LTD key whose path relative to the build prefix is an excluded cache path. It uses the same `docverse.excluded_paths` list the client applies to `docverse upload` tarballs: `.doctrees/`, `.buildinfo`, `__pycache__/`, VCS directories, and the rest. These keys are never downloaded, hashed, or written to R2, so Sphinx's `.doctrees/` pickles (about 64 MB per ts-xml build, which buffered whole are what OOM-killed the sync worker) stay in LTD. The build's `content_hash` covers only what Docverse serves, so a keeper-synced build still converges with a client upload of the same tree. Each copy reports how many keys it left behind as `excluded_object_count`, which appears on the `Copied build content` and `Empty source prefix; nothing to copy` log lines and as a new nullable field on the `build_content_copied` metrics event. The field is a key count with no byte total, because LTD's listing carries no sizes, and it is null when the copy failed before it listed the prefix. An LTD prefix that holds only caches counts as empty, so the edition-prefix fallback for an `AccessDenied` build prefix still re-raises the denial instead of importing an empty build. Builds that were already synced are not rewritten: they keep their cache objects and their existing `content_hash`, and keeper-sync's state short-circuit keeps them from being copied again. Only a new LTD build is hashed and copied without its caches.
