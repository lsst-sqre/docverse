### Bug fixes

- A GitHub outage no longer strands a project's `installation_status` on `not_installed`. The `project_github_resolve` worker now raises `arq.Retry` with an exponential backoff when GitHub could not answer the attempt — a transport failure, a 5xx, or a rate limit — and arq re-runs the job up to four times over roughly seven minutes. Before this, the resolve got exactly one attempt: a blip during it left `github_installation_id` NULL with no periodic backfill and no self-heal, so the API reported `not_installed` for a repository the App *is* installed on until an operator re-`PATCH`ed the binding. Errors a retry cannot fix — an unparseable private key, a 401, a 403 that is not a rate limit — still fail on the first attempt, and the expected `not_installed` outcome is unchanged.

### Other changes

- `arq.Retry` no longer opens a Sentry issue. The `instrument_arq_task` wrapper catches `Exception` to give arq the Sentry integration it lacks, and `arq.Retry` is a `RuntimeError` subclass, so a task that defers itself would otherwise page once per attempt for a condition nobody can act on. A task that exhausts its retry budget still reports its terminal failure.
