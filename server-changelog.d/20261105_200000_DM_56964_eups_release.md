### New features

- New `eups_release` edition tracking mode follows the latest final EUPS release tag. It parses `v?MAJOR<sep>MINOR[<sep>PATCH][<sep>rcN]` with `_`, `.` or `-` as the separator, so `v17_0` (patch 0) sorts below `v17_0_1`, which sorts below `v30_0_12`. Builds whose ref is a release candidate (`v30_0_12_rc3`), a weekly or a daily never match the edition, a build on an older release than the one served is skipped, and a current build whose ref is not a release (a `main` build, say) is replaced by the first final release that arrives regardless of build dates. PATCH a project's `__main` to `{"tracking_mode": "eups_release"}` to serve the latest release at the project root. No database migration is needed.

### Other changes

- The EUPS major, weekly and daily version grammars now also accept `-` as a separator, so legacy LTD edition slugs such as `13-0`, `v16-0` and `w-2018-06` parse and order alongside their underscore forms. A build on such a ref now matches the `eups_major` or `eups_weekly` built-in slug rule, so it derives the `release` kind instead of falling through to `draft`; the derived slug is still the ref verbatim.
