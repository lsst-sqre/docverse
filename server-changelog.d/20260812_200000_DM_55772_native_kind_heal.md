### Bug fixes

- The native build-upload path now heals an existing edition's kind the same way keeper-sync does, so a natively-created project no longer diverges from a migrated one. `EditionTrackingService.track_build` previously only moved the build pointer on editions returned by `find_matching_editions`, so a version-slugged edition created before the built-in version rules landed stayed `draft` forever — holding the short CDN cache profile and staying eligible for `draft_inactivity` soft-deletion — while the byte-identical edition on a keeper-sync-migrated project was corrected on every sync. `track_build` now re-derives the kind for every matched edition and converges the ones Docverse owns, so the next tracked build for the ref heals it. The sweep only touches editions the ref derivation actually describes: the project's `__main` edition and the `N` / `N.M` semver aggregates carry structural kinds no ref derivation computes, and are left alone. Each change emits a `Converged edition kind` log event carrying the previous kind, the new kind, and the rule type that matched.
