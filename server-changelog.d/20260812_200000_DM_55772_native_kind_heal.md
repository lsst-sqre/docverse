### Bug fixes

- The native build-upload path now heals an existing edition's kind the same way keeper-sync does, so a natively-created project no longer diverges from a migrated one. `EditionTrackingService.track_build` previously only moved the build pointer on editions returned by `find_matching_editions`, so a version-slugged edition created before the built-in version rules landed stayed `draft` forever — holding the short CDN cache profile and staying eligible for `draft_inactivity` soft-deletion — while the byte-identical edition on a keeper-sync-migrated project was promoted to `release` on every sync. `track_build` now re-derives the kind for every matched edition and applies it under the same promote-only gate, so the next tracked build for the ref heals it. Only `draft` → `release` is ever written: kinds are never demoted, `main` / `major` / `minor` / `alternate` editions are never rewritten, and a kind set by hand through the editions PATCH API survives every subsequent upload. To durably suppress the release classification for a project, add a `slug_rewrite_rules` entry (e.g. `{"type": "semver", "edition_kind": "draft"}`) rather than PATCHing the edition to `draft`. Each promotion emits a `Promoted edition kind` log event carrying the previous kind and the rule type that matched.

### Other changes

- The promote-only kind policy shared by keeper-sync's per-sync refresh and the native tracking path now lives in one place, `docverse_server.domain.edition_kind.is_kind_promotion`, instead of being an allow-list private to the keeper-sync service.
