### New features

- Keeper-sync build-content copies now report themselves to Sasquatch. Every copy publishes one project-scoped `build_content_copied` event, after it succeeds and after it fails, carrying the LTD product slug, the objects and bytes stored, the duration, the peak number of concurrent object copies, the number of objects that landed only after an upload retry (`retried_object_count`), the number whose upload ran out of its retry budget (`exhausted_object_count`), whether the build-level retry re-ran the copy (`build_retry_used`), and whether it finally succeeded. A copy the build-level retry re-ran is still one event, with its transport counts summed over both passes, so a dashboard can plot R2 transport health across a sync campaign: rising `retried_object_count` is R2 getting flaky while the per-object budget still absorbs it, and `exhausted_object_count` above zero is an object that outlasted that whole budget. The worker's "Copied build content" log line carries the same two counts.
