### Bug fixes

- `edition_reconcile` no longer fails when Cloudflare's KV `bulk/get` endpoint is slow to answer. The Cloudflare KV client issued every request with the flat 5 s timeout of the HTTP client it shares with discovery, GitHub and CDN purges. On 2026-10-19 `bulk/get` against the production namespace began answering in either ~0.5 s or ~5.4 s on about half of all calls, regardless of how many keys were asked for, so every attempt of the read-back's 4-attempt budget timed out a few hundred milliseconds before the answer arrived, and `edition_reconcile` failed 4 of its 5 ticks for the `rubin` organization with `httpx.ReadTimeout`, leaving any drifted pointer unrepaired. Cloudflare KV requests (the pointer write, delete and bulk read-back) now carry their own per-request timeout (10 s connect, 30 s read and write, 30 s pool), so a stalled call becomes a ~5.4 s success. The retry budget, the 100-key chunk size and the shared client's defaults for everything else are unchanged, the timeout is a fixed constant rather than a setting, and the API process's unpublish path gets the same timeout. A reconcile of ~4,400 pointers in which every chunk stalls grows by about four minutes, inside the maintenance job timeout.
