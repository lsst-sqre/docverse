### Bug fixes

- Semver aggregate auto-creation now keys off the git ref's own semver grammar rather than the edition kind the slug-rewrite chain settled on. User-configured rules are consulted before the built-in `semver` heuristic, so a rule that exists only to reshape a slug — say `{"type": "prefix_strip", "prefix": "v"}` to turn `v16.0.0` into the `16.0.0` edition — left the derived kind at its `draft` default and silently suppressed the `16` and `16.0` aggregates, with no error anywhere. The native upload path and keeper-sync's backfill now both create the aggregates for any stable semver ref, so the two continue to produce identical rows for a migrated and a natively built project. Prereleases such as `1.0.0-rc.1` and non-semver refs still create no aggregates, and `edition_autocreation.semver_aggregates = false` remains the explicit way to turn aggregate creation off.
