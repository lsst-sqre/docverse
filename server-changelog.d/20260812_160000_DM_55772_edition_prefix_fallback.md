### Bug fixes

- keeper-sync now recovers LTD's oldest build content instead of failing it. LTD's earliest uploads wrote their build objects (`<product>/builds/<build-slug>/`) without a public-read ACL, so the deliberately-anonymous `LtdS3Source` was denied every one of them and the affected editions imported with no build at all — 19 of documenteer's editions (`0.3` … `0.5.6`) failed the 2026-08-12 roundtable-dev sync this way and served 404s. LTD's publish step, however, also copied the same bytes to the edition prefix, `<product>/v/<edition-slug>/`, and *that* copy is public — it is what Fastly serves. `sync_build` now resolves its source prefix once per build and, on an `AccessDenied` from the build prefix, re-reads the content from the edition prefix; the resolved prefix feeds both the manifest hash and the copy, so the `content_hash` recorded on the build always describes the bytes that were uploaded. No AWS credentials are involved: the source stays `UNSIGNED`. The fallback is a recovery path, not a new default — a readable build prefix is never re-hashed or re-copied and never consults the edition prefix, a missing or empty build prefix is not a denial and does not trigger it, the default (`main`) edition is excluded because LTD serves it from the product root rather than from `v/`, and a fallback that finds nothing re-raises the denial rather than finalizing a zero-object build that would look synced while serving 404s. Provenance is recorded on the build's `keeper_sync_state` row (`ltd_source_prefix`, `ltd_source_prefix_origin`) and in the sync log, so a build whose bytes did not come from its own `bucket_root_dir` stays identifiable after the fact.

### Other changes

- `LtdS3Source` now raises `LtdSourceAccessDeniedError` instead of letting botocore's raw `ClientError` escape when the anonymous principal is denied a bucket key, so callers can tell "this content is unreadable" apart from "this key is missing" or "S3 is unhappy right now" without inspecting a response dict.
