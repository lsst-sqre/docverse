### Bug fixes

- Keeper-sync no longer imports every non-`main` LTD edition as a `draft`. `derive_edition_kind()` now runs the tracked ref through the full slug-rewrite rule chain — org/project rules plus the built-in version heuristics — falling back to the LTD slug when LTD supplies no ref (which it does for every non-`git_refs` mode, where the slug is itself the version string). LTD's version tracking modes narrow but do not decide: `lsst_doc`, `eups_major_release`, and `eups_weekly_release` only describe which grammar an edition prefers — LTD's own `lsst_doc` mode publishes `main` builds until a version tag exists — so a branch-tracking edition under any of them imports as `draft` rather than being certified a release it never was. `eups_daily_release` is the one mode that decides alone, and it decides `draft` so dailies keep ageing out under `draft_inactivity`. LTD's `main` edition still maps onto `EditionKind.main`.
- The keeper-sync preemptive lifecycle pass stops tombstoning version-slugged LTD editions `lifecycle_preemptive` before they are ever imported. The transient edition it evaluates now carries the same derived kind as the import path, so `draft_inactivity` no longer matches old LTD releases regardless of their `date_rebuilt` age. Already-tombstoned editions are not re-imported automatically — an operator must delete the `lifecycle_preemptive` tombstones and re-run the sync.
