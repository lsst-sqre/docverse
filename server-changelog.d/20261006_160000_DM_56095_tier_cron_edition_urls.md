### Bug fixes

- The `keeper_sync_tier_discovery` and `keeper_sync_tier_other` crons no longer fetch every edition of each in-scope LTD product. Both only need each edition's LTD id, which the edition's URL already carries, but they called `LtdClient.list_editions_for_product`, which follows the URL list with one `GET /editions/<id>` per edition. On roundtable-prod on 2026-10-06, after `pipelines` (2,938 LTD editions) entered the `rubin` organization's scope, both crons hit arq's 300 s cron timeout on every tick. They now make one LTD call per polled project, `GET /products/<slug>/editions/`, and read the ids off the URLs: discovery looks each id up in the organization's edition state, and the other tier reads the state rows of the listed ids. Because the other tier no longer sees edition slugs, it recognises `main` by the LTD id `keeper_sync_tier_main` caches on the project's state (`main_edition_ltd_id`) and leaves it out as before. A project whose `main` id is not cached yet, because `keeper_sync_tier_main` has not resolved it, has every listed edition checked, `main` included. At worst that enqueues one `keeper_sync_project` that `keeper_sync_tier_main` might also have: the per-project active-job slot still allows only one, and the sync skips every edition LTD has not rebuilt since it was last seen.
