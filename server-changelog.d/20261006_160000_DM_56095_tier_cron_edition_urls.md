### Bug fixes

- The `keeper_sync_tier_discovery` and `keeper_sync_tier_other` crons no longer fetch every edition of each in-scope LTD product. Both only need each edition's LTD id, which the edition's URL already carries, but they called `LtdClient.list_editions_for_product`, which follows the URL list with one `GET /editions/<id>` per edition. On roundtable-prod on 2026-10-06, after `pipelines` (2,938 LTD editions) entered the `rubin` organization's scope, both crons hit arq's 300 s cron timeout on every tick. They now make one LTD call per polled project, `GET /products/<slug>/editions/`, and read the ids off the URLs: discovery looks each id up in the organization's edition state, and the other tier reads the state rows of the listed ids. Because the other tier no longer sees LTD's edition payloads, it recognises `main` by the LTD slug each edition's state row records and leaves it out as before, so an old `main` alone never enqueues a sync from the other tier. A listed URL with no trailing integer id is skipped rather than allowed to fail the tick: the tier logs one `Keeper-sync tier skipped unparsable LTD edition URLs` warning naming the organization, the project and the URLs, still checks the project on the ids that did parse, still marks it polled, and goes on to the rest of the organization's scope.
