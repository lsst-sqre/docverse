### Bug fixes

- Fixed a deadlock between `DELETE /orgs/{org}/projects/{project}` and a concurrent repoint of one of that project's editions. `EditionStore.set_current_build` held a shared lock on the target build while it waited for the project row, which is the reverse of the order the project soft-delete cascade takes those rows in, so PostgreSQL aborted one of the two transactions — and neither `keeper_sync_project` (which runs with `max_tries=1`), the DELETE handler, nor the edition PATCH has anywhere to retry. Every writer that touches more than one of `projects`, `editions`, and `builds` now takes them in one order: projects, then editions, then builds. `PATCH /orgs/{org}/projects/{project}/editions/{edition}` carrying both a metadata field and `build` applies the build override before the metadata write for the same reason. The guards that refuse a stale or deleted build are unchanged.
