### New features

- `GET /orgs/{org}/projects` accepts an `include_deleted` query parameter. When true the listing also returns soft-deleted projects and counts them in `X-Total-Count`, on the fuzzy-search path (`q=`) as well as the ordered listing, so a consumer mirroring the listing sees a deletion as a row it can act on rather than as a project that silently stopped appearing. It defaults to false, which is the previous behaviour.
- `GET /orgs/{org}/projects/{project}` accepts the same `include_deleted` flag: with it, a soft-deleted project is returned instead of 404ing. Slugs are never reused after a delete (`uq_projects_org_slug` ignores `date_deleted`), so the widened lookup can only ever resolve the project that already owned the slug. The flag is read-only — PATCH and DELETE still 404 on a soft-deleted project.
- The project resource gains a `date_deleted` field, always present and `null` for a live project, carrying the deletion timestamp for one returned behind `include_deleted`.
