### Bug fixes

- The transport-retry log lines now say what failed and for how long. `str(httpx.ConnectTimeout())` is the empty string, so "Retrying … after transport error" (logged by every retrying storage client: the LTD client, the Cloudflare cache purger, the Cloudflare KV edition publisher and the object store) and the object store's "Presigned upload failed" both logged `error=""` for the R2 connect timeouts that failed keeper-sync copies. Both now log the exception's `repr` in `error` (alongside the existing `error_type`). The retry line also carries `elapsed_seconds` since the first attempt, next to its `attempt`, `max_attempts` and `retry_delay`, and both "Presigned upload failed" lines (transport and status) carry `elapsed_seconds` next to `attempts`, so a Sentry event says how long the object was tried before the budget ran out.
