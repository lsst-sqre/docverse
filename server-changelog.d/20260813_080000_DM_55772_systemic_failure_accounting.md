### Bug fixes

- A keeper-sync project whose only failures are permanent per-edition faults no longer fails its job. `sync_project`'s end-of-run systemic check read "failures, and no edition reached LTD" as an outage, but tombstone short-circuits and build-less editions are deliberately neutral for that LTD-contact signal — so a migrated product with 19 `lifecycle_preemptive` tombstones and one edition denied at both `builds/<slug>/` and `v/<slug>/` computed zero successes and raised `KeeperSyncSystemicFailureError`. The job was marked `failed`, the parent run rolled up `partial_failure`, Sentry fired, and the 5-minute tier cron replayed the identical run forever, when the `completed_with_errors` / `edition_failures` partial-success path exists for exactly that permanent fault. The check now reads the signal by failure *type*: `LtdSourceAccessDeniedError` is permanent by construction (the object carries no public-read ACL and the anonymous LTD source has no credentials to acquire one, and LTD is read-only source material), so a run whose failures are all permanent completes with errors and logs why it imported nothing. A run with any other failure shape — a transport error, a dead database — still raises, still chains from that failure rather than an incidental denial beside it, and the consecutive-failure breaker is unchanged.
- `KeeperSyncSystemicFailureError` messages now name at most 20 failed edition slugs, with a `(+N more)` suffix for the remainder. `str(exc)` is copied verbatim into the failing job's `queue_jobs.errors['message']` JSONB and becomes the Sentry issue title, so the unbounded join wrote multi-KB blobs into the job record and gave each run a title unique enough to defeat Sentry grouping — up to 75 slugs at the consecutive-failure raise and the project's whole edition list (279 on documenteer) at the end-of-run raise. The cap matches the one already applied to the partial-success job `progress` payload and terminal log line; counts stay exact, and `failed_ltd_edition_slugs` still carries every slug for programmatic callers.
