### New features

- New endpoint `POST /orgs/{org}/keeper-sync/scope-preview` (org admin) resolves a keeper-sync scope against the live LTD product listing without persisting or enqueueing anything. The optional request body is a `KeeperSyncConfigUpdate` merged over the stored config exactly as `PATCH` merges it — and validated exactly as `PATCH` validates it — so an operator can check a candidate scope before saving one. That check matters because saving is not inert: the tier crons act on the stored config at their next tick. An empty body previews the stored config, and the preview works whether or not sync is `enabled`.
- The preview reports `ltd_count` and `in_scope_count`, the resolved `in_scope_slugs` in LTD listing order, `new_slugs` (in-scope slugs with no keeper-sync state row yet — what the next backfill would import for the first time), and `tombstoned_slugs` (in scope by config but skipped for a tombstone).
- The preview also catches typos in the two exact-slug config fields, reporting each field separately: `unmatched_project_slugs` for `project_slugs` entries the LTD listing does not contain, and `unmatched_exclude_project_slugs` for `exclude_project_slugs` entries. They are separate lists because a miss means different things — an unmatched include admits nothing and is almost always a misspelling, while an unmatched exclude holds nothing back, so it is either a misspelling (and the product it was meant to stop syncs anyway) or a stale entry for a product since deleted from Keeper, which is harmless. A slug named in both fields and absent from LTD is reported under both; each list de-duplicates within itself and keeps config order. The pattern fields are checked by neither, since a pattern matching nothing is a legitimate way to stage a future wave.

### Other changes

- A failure fetching the LTD product listing during a scope preview is reported as a 502 carrying LTD's own status rather than a Docverse 500, through a new `UpstreamServiceError`. Unlike the keeper-sync worker's LTD failures it raises no Slack or Sentry alert: the org admin who triggered the call sees the failure synchronously in the response.
