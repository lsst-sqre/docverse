### Bug fixes

- A build now gets its own `/v/<slug>/` edition whenever no matched edition already owns its git ref, instead of only when nothing matched at all. Before, any alias edition absorbed the upload: with `__main` in `eups_release`, a `v30_0_13` build advanced `__main` but never created `v30_0_13`, and a `weekly` (`eups_weekly_release`), `daily` (`eups_daily_release`), `latest` (`semver_release`), semver aggregate or `lsst_doc` edition did the same to `w_2026_46`, `d_2026_11_05`, `v2.0.0` or `v1.3`, so pipelines, technotes and semver projects lost the per-version history LTD kept. A matched edition owns the ref only when it tracks that literal ref (`git_ref` or `alternate_git_ref` mode) or already holds the derived slug, so `__main` tracking `main` still keeps a `main` build from creating a `main` edition. Matches in every other mode advance beside the new edition exactly as before. The per-ref edition is created, or revived after a lifecycle delete, through the same path as other auto-created editions; a slug an operator deleted stays deleted. One consequence: a project whose `__main` is in `lsst_doc` mode now gets a draft edition for its default branch from the first default-branch build, rather than only once a version tag has moved `__main` off the branch, as it did on LTD. There is no setting for this rule; an `ignore` slug rewrite rule still suppresses a ref entirely. Keeper-sync is unaffected. See `docs/edition-tracking.md`.
- An existing edition that a build's ref reuses because it already holds the derived slug, without matching the build (such as a `git_ref` edition named `v30_0_13` that tracks another ref), is now reported as `updated` in edition tracking's outcomes and the build-processing job's `editions_updated`, rather than `created`: it is pointed at the build as before, but nothing was created.
- The warning edition tracking logs when an operator's delete reserves a derived slug is now "Edition slug reserved by manual delete; edition not recreated", replacing "Edition slug reserved by manual delete; build not tracked". The old wording was wrong whenever the build also matched an alias edition such as `__main`, which still advances.
