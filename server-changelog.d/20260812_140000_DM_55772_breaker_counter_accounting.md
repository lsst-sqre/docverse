### Bug fixes

- Keeper-sync's systemic-outage breaker no longer treats a tombstoned edition as proof that LTD is healthy. `sync_project` counts consecutive `sync_edition` failures and aborts the project once the run looks systemic rather than per-edition, but it reset that counter after *any* `sync_edition` that returned — including the tombstone short-circuit, which returns on a single `keeper_sync_state` read without contacting LTD at all. A database read succeeds especially well while LTD is down, so on any project with tombstoned editions scattered through its list an outage produced exactly the alternating fail/reset pattern that defeats the counter: the run walked every remaining edition, finished `completed_with_errors`, and presented a shared fault as a series of isolated per-edition ones. The guard was weakest in precisely its motivating scenario. `EditionSyncOutcome` now carries an explicit `short_circuited` flag — mirroring `BuildSyncOutcome`, and preferred over inferring it from `build_outcome is None`, which is also true of a legitimately build-less edition — and only a non-short-circuited outcome resets the counter, matching how editions skipped by the proactive lifecycle pass have always been counter-neutral. What gets synced, what lands in `edition_outcomes`, and the `on_edition_synced` fan-out are all unchanged.

- The consecutive-failure threshold is raised from 5 to 75, re-derived now that fixing the reset makes the guard reachable for the first time. Its original justification — that LTD's un-ACL'd uploads are scattered through a product's history rather than contiguous — was wrong: measured on roundtable-dev, documenteer's build slugs 1–204 deny anonymous reads and 205+ succeed, 60 of its editions point at builds inside that block, and LTD lists editions oldest-first, so those permanent failures arrive back-to-back. At 5 the first sync after the fix would have aborted inside the denial block on every poll and never imported the readable releases behind it, which is a far worse failure than the one the breaker prevents: a missed abort still finishes `completed_with_errors` with an exact `edition_failure_count` and rolls the parent run up `partial_failure`, while a false abort is permanent and total. 75 clears the observed 60-edition block with headroom and still aborts inside the first ~27% of documenteer's 279 editions.
