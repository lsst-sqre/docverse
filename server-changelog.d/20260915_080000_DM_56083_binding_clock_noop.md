### Bug fixes

- A GitHub-binding write that changes nothing no longer advances a project's `date_updated`. The four writers — the `installation`, `repository.renamed`, and `repository.transferred` webhook processors, plus the resolve worker's `update_github_metadata` — now predicate their `UPDATE` on the binding columns actually differing, so a redelivered `installation.created` listing 40 already-scoped repos matches zero rows instead of retiring 40 project `ETag`s and re-emitting 40 identical rows into every `updated_since` window.
- `PATCH /orgs/{org}/projects/{project}` enqueues a `project_github_resolve` job only when the request actually rewrites the GitHub binding. A title-only edit of a bound project used to queue one maintenance job per request whose sole effect was to re-read the ids already stored, and — before the fix above — to stamp the project's clock a second time seconds after the `PATCH` had stamped it. A bulk retitle of 100 projects cost 100 jobs and 100 phantom change signals; it now costs neither.
