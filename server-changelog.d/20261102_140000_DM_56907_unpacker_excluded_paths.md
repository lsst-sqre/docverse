### New features

- The build-processing worker now skips excluded cache paths when it unpacks an uploaded tarball, completing the ingest filter that keeper-sync's copier already applies. It uses the same `docverse.excluded_paths` list, so `.doctrees/`, `.buildinfo`, `__pycache__/`, VCS directories and the rest are never read, hashed, or uploaded, wherever they sit in the tree, including inside a nested sub-site. This is the backstop for `docverse upload` and upload-action releases that predate the client-side filter and still put Sphinx's caches in their tarballs. A build's `object_count`, `total_size_bytes` and `content_hash` cover only the files Docverse serves, so a client upload and a keeper-synced copy of the same tree still converge on one `content_hash`, whichever client produced the tarball. The `Upload complete` log line and the `build_processed` metrics event report the skipped files as `excluded_object_count` and `excluded_bytes` (from the tar headers). Both fields are new and nullable on the event, and they are null when nothing was unpacked. A tarball that holds nothing but cache paths completes as a zero-object build with the existing `Tarball contained no extractable files` warning, as an empty tarball does.
