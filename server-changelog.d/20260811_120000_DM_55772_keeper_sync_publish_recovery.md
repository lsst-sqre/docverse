### Bug fixes

- A keeper-sync run's project fan-out no longer collapses when one project loses the race for its active-job slot. `keeper_sync_run_discovery` paired a `has_active_for_subject` pre-check with a plain insert, so the 5-minute `keeper_sync_tier` cron claiming the same LTD slug in the window between the `SELECT` and the `INSERT` raised an `IntegrityError` from inside the per-slug loop. That escaped to the discovery function's outer handler, which marked both the discovery job and the entire run failed — silently dropping every remaining in-scope project. The fan-out now uses the same race-tolerant insert the tier crons do, so a lost race skips only the contended project and the rest of the run proceeds. Run bookkeeping is unaffected: a run has no stored expected-child count, so a skipped project simply never enters the aggregate that finalises it, and the `pending` → `in_progress` transition still fires on the first child that actually lands.

- Semver aggregate editions whose publish enqueue was lost now recover on the next sync. The `15` / `15.2` aggregates get exactly one publish enqueue, from the `on_edition_synced` callback, and three things could swallow it: the enqueue raising (`sync_project` deliberately absorbs callback failures), the worker dying between the backfill's commit and the enqueue, or the backfill itself failing after committing an earlier aggregate. In every case the aggregate row pointed at the release build with its KV pointer never written, and nothing recovered it — the tail-end self-heal pass iterated only the LTD editions' in-memory outcomes, and on re-sync the backfill emits no outcome for an aggregate already pointing at the right build. The self-heal pass now covers the aggregates too, healing from persistent state rather than from this run's outcomes so all three loss modes are caught. Whether an aggregate needs healing is decided per `(edition, build)` pair from its `edition_build_history` row rather than from the edition's own `publish_status`, which survives a repoint and would read `published` for an aggregate advanced onto a new build with a lost enqueue; a publish already in flight, or one that previously succeeded or failed, is still left alone.
