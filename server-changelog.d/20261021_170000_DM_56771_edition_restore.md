### New features

- `POST /orgs/{org}/projects/{project}/editions/{edition}/restore` brings back a soft-deleted edition in place, returning it with `200`. It works whatever deleted the edition, so it is the way back from an admin `DELETE`, which neither a new build for the edition's ref nor a keeper-sync of its LTD edition will undo. The edition keeps its id, slug, kind, tracking, and build history; a keeper-sync tombstone on it is cleared, so it leaves `GET /orgs/{org}/keeper-sync/tombstones` and keeper-sync syncs it again. The edition's current build is published again (on the pair's existing history row; a restore records no new history entry) unless that build was itself deleted or purged, in which case the edition comes back unpublished and a warning is logged. The project's dashboard is rebuilt and one `edition_lifecycle` metrics event with the `restore` action is published. Admin-only, like the `DELETE` it reverses. An edition that is not deleted answers `404`, as does `__main`, which cannot be deleted.
