### Bug fixes

- A GitHub-binding write now advances the affected project's `date_updated`, so a poller watching `GET /orgs/{org}/projects` sees it. The four writes — the resolve worker landing the `github_*_id` columns, and the `repository.renamed`, `repository.transferred`, and `installation` webhook processors — used to pin the clock as "sync bookkeeping". That was wrong once the clock became a change signal: each of them moves `github_owner`, `github_repo`, or `github_installation_id`, and therefore the project's `source_url` or its binding's `installation_status` on the wire, while the listing's `ETag` and its `updated_since` filter both stood still. A consumer holding a cached copy was told `304 Not Modified` over a project whose source coordinates had in fact changed.
