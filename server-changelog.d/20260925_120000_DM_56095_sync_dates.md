### Bug fixes

- Keeper-synced editions and builds now carry LTD Keeper's timestamps instead of the moment Docverse imported them, so a migrated project's version dashboard (`/v/`) no longer reads "updated just now" for every edition. `editions.date_created` / `date_updated` take the LTD edition's `date_created` and `date_rebuilt` (or `date_created` when LTD never rebuilt it); the edition's current build takes the LTD build's `date_created` as both `date_created` and `date_completed`; and the `N` / `N.M` semver aggregates serving a release's build take that release's `date_updated`. Keeper-sync re-asserts these dates as the last step of every edition visit, so a Docverse-side write drifts a synced row's clock for at most one visit, and a visit that only moved dates enqueues one `dashboard_build` for its project. The project summary log line (`Keeper-sync project completed`) now carries `restamped_edition_count`. `projects.date_updated` is never touched, so `updated_since` pollers do not see a restamp as a content change. Projects synced before this release are backfilled by launching a full org sync run (`POST /orgs/{org}/keeper-sync/runs`).

### Other changes

- Because `draft_inactivity` judges a draft by `date_updated`, a keeper-synced draft is now judged on LTD's last rebuild: a draft imported before this release whose LTD `date_rebuilt` is older than `max_days_inactive` is soft-deleted on the first `lifecycle_eval` tick after a visit restamps it. Set `lifecycle_exempt` beforehand on any draft that should survive. `docs/keeper-sync-scope.md` gains a "Timestamps mirror LTD" section covering which columns follow LTD, the per-visit re-assertion, the `draft_inactivity` consequence, what the stamp leaves alone, and the backfill recipe; it is linked from `docs/index.md` and from the `DraftInactivityRule` description.
