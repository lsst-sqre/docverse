### New features

- Docverse now records each GitHub-bound project's default branch. A new nullable `projects.github_default_branch` column (alembic revision `c0d1e2f3a4b5`, no data step) is filled by the `project_github_resolve` worker from the `GET /repos/{owner}/{repo}` response it already fetches, alongside the numeric ids, and surfaces read-only as `github.default_branch` on the project resource. It reads `null` until Docverse has learned it; existing projects are filled by their next resolve. `POST` and `PATCH` on `/orgs/{org}/projects` reject a `github.default_branch` with a 422, because GitHub is the source of truth. A resolve that finds the stored value unchanged leaves the project's `date_updated` alone. This is the first step toward `__main` following a default-branch rename (PRD #721); nothing reads the column yet.
