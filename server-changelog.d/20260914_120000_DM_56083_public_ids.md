### New features

- Projects and organizations now carry a stable, time-ordered Crockford Base32 public identifier, exposed as `id` on the `GET /orgs`, `GET /orgs/{org}`, `GET /orgs/{org}/projects`, and `GET /orgs/{org}/projects/{project}` responses (and on the admin organization resource). Like build, queue-job, and keeper-sync-run IDs, it is minted in application code rather than by a sequence, so no integer row id ever reaches the wire. Path parameters remain slugs; the ID is what stays constant if a slug is ever renamed.
- Two Alembic revisions (`f7a8b9c0d1e2` for `projects`, `a8b9c0d1e2f3` for `organizations`) add the `public_id` column and backfill existing rows in `date_created` order, so IDs minted for rows that predate this change still sort in creation order. Neither ID appears in any object-store key, so the backfill is safe to run against a populated database in one pass.
