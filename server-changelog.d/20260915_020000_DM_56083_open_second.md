### Bug fixes

- A date-only conditional GET is no longer answered `304 Not Modified` while the resource's watermark still falls in the server's current second. `Last-Modified` carries whole seconds, so a write that lands later in the same second as the value a client was given used to be invisible to the `If-Modified-Since` comparison and stayed hidden until some unrelated later-second write moved the clock again (RFC 7232 §2.2.1). The project listing, the single project, and `GET /orgs/{org}` now answer such a request in full and let the date earn a 304 only once its second has closed. `If-None-Match` hashes the watermark at microsecond precision and is unchanged, so an ETag poller was never affected and pays nothing for the fix.
