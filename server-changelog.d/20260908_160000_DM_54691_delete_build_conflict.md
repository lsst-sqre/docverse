### Backwards-incompatible changes

- `DELETE /orgs/{org}/projects/{project}/builds/{build}` now answers 409 when a live edition holds the build as its current build, instead of deleting it. The response names every edition serving it, so the fix is in the message: roll those editions back to another build and the DELETE goes through. This closes the gap that made the purgatory sweep unsafe — a deleted build's objects are reclaimed once the organization's retention elapses, and until now nothing stopped an operator from deleting the build an edition was still resolving to. The API now says what the lifecycle reaper already enforced: its `build_history_orphan` rule has never reaped a build an edition points at. A soft-deleted edition's pointer does not refuse anything, because nothing serves a deleted edition.
