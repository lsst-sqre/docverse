### Bug fixes

- Keeper-sync no longer leaves an LTD edition retired by a lifecycle rule vetoed forever after its author pushes again. When LTD has rebuilt an edition since its `lifecycle_preemptive` or `lifecycle_delete` tombstone last saw it (LTD's `date_rebuilt` later than the state row's `date_rebuilt_seen`, or its `date_tombstoned` when it has none), the next project sync judges the rebuilt edition against the project's `draft_inactivity` and `ref_deleted` rules again, from the LTD payload already in hand and the sync's live ref set. When no rule matches any more, the tombstone is cleared (a `lifecycle_delete` edition's soft-deleted row is revived in place, keeping its id), the edition is imported, published, and announced with an `edition_lifecycle` event with the `restore` action, all in the same sync. When a rule still matches — such as a trailing LTD build of a merged-and-deleted branch — the tombstone stays, its `tombstone_note` names the rule that matched this time, and the rebuild is stamped on the row so it is not judged again until LTD rebuilds the edition once more. A draft retired for duplicating `__main` (a `draft` tracking, in `git_ref` mode, the ref `__main` tracks) keeps its tombstone the same way while it still duplicates `__main`, though no rule matches it, so an active default branch does not bring the duplicate back on every push. A failed GitHub ref read keeps the tombstone and leaves the rebuild to be judged on the next sync; a project without a GitHub binding is judged with `ref_deleted` matching nothing. `manual_delete` tombstones are still a permanent veto. Keeper-sync now settles a soft-deleted edition still holding a synced edition's slug the way native edition tracking does: revived when a lifecycle rule (or nothing on record) deleted it, and skipped with the warning "Edition slug reserved by manual delete; LTD edition not imported" when an operator did, instead of failing the edition with "lost ON CONFLICT race". The `keeper_sync_project` completion log lines report `tombstones_cleared` and `tombstones_kept` counts.
