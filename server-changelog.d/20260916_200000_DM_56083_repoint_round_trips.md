### Other changes

- An edition repoint costs fewer database round trips. `EditionStore.set_current_build` now reads the target build's `date_deleted` and `date_created` in the single `FOR SHARE` statement that already locks that row, instead of selecting it a second time, and drops a `refresh` of the edition row it re-queries immediately afterwards. It also takes the `projects` row by primary key when the caller says which project the edition belongs to, and not at all when the caller says the edition is not that project's `__main` — the majority of repoints, and the only kind that never writes that row. A `__main` repoint on the upload-tracking path now issues four statements before its write rather than five; the lock order, both guards, the project clock stamp, and the `unchanged` outcome are untouched.
- `EditionStore.set_current_build` and `EditionStore.lock_for_repoint` take optional `project_id` and `is_default` arguments, and every repoint in the tree — the edition service's `build` override and rollback, edition tracking, and keeper-sync — now passes them from the `Edition` it already holds. Without them both methods fall back to the subquery they used before. `Edition` gains an `is_default` property for the purpose.
