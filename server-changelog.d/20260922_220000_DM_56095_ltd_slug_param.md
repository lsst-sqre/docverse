### Other changes

- The `{ltd_slug}` path segment on `GET /orgs/{org}/keeper-sync/projects/{ltd_slug}`, its `/editions`, and `POST …/refresh` is now constrained to what LTD Keeper itself accepts for a product slug (`^[a-z][-a-z0-9]*[a-z0-9]$`, at most 255 characters) and is documented that way in the OpenAPI schema. A slug outside that class is a 422 rather than a 404, and — the point of the change — an arbitrarily long path segment no longer reaches the org's operator-supplied scope patterns, whose worst-case matching cost grows with the length of the subject string. Every slug LTD can issue is unaffected.
- The org lookup, `enabled` check and scope check those three endpoints run before doing anything else now live in one shared helper (`services/keeper_sync_gate.py`) instead of being copy-pasted into three services, so the 404 message `is not in the keeper-sync scope` that the docs treat as a contract has exactly one definition. No status code or message changed, including `POST …/keeper-sync/runs` keeping its 409 for a sync-disabled org.
