### Bug fixes

- Enqueuing a queue job that loses the race for an active-job slot is now a clean skip rather than an error. The `queue_jobs` table carries partial unique indexes that allow at most one `queued`/`in_progress` row per subject, and the application-side `has_active_*` pre-checks in front of them are a fast path, not a guarantee — a concurrent worker can claim the slot between the `SELECT` and the `INSERT`. `QueueJobStore` now offers a race-tolerant insert that absorbs exactly that conflict inside a savepoint and returns "no job" instead of raising, leaving the caller's transaction usable. Two call sites use it. Keeper-sync's tier crons no longer abandon every remaining project in an organization for the tick when one project's enqueue loses the race — only the contended project is skipped. The dashboard-build cascade (which fires once per successful edition publish, so one release now fans out several times) no longer reports these benign duplicates to Sentry; genuine enqueue failures still report. Any other integrity error still propagates untouched.
