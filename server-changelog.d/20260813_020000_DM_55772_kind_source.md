### Backwards-incompatible changes

- The `editions.kind_manually_set` boolean is replaced by an `editions.kind_source` enum (`derived` | `declared`); an Alembic migration adds the column, backfills `declared` wherever the flag was set and `derived` everywhere else, and drops the flag. The boolean answered "did a PATCH mention `kind`?", which was a proxy for the question the heal paths actually ask — *who owns this edition's kind?* — and it was stamped on the mere presence of `kind` in a payload, so a read-modify-write client that echoed back the kind it had just GET-ed opted that edition out of healing invisibly and with no way to undo it. `kind_source` records ownership directly and every writer of `kind` stamps it in the same statement: POSTing an edition declares its kind, system creation (project defaults, auto-creation, the semver aggregates, keeper-sync imports) derives it, a PATCH declares only when it *changes* the kind, and the heal paths re-assert `derived`.

### New features

- `kind_source` is exposed read-only on the edition response model, and `EditionUpdate` accepts it so an operator can hand a declared kind back to Docverse: PATCH `{"kind_source": "derived"}` and the next sync or tracked build re-derives the kind from the edition's ref and the project's slug-rewrite rules. Echoing an unchanged `kind` is now a no-op — convergence, not a re-asserting PATCH, is how an automatic kind is undone — and an explicit `kind_source` in the same PATCH as a `kind` change wins, so "correct this and hand it back" is one request.

### Bug fixes

- Alternate editions now derive `kind=alternate` instead of inheriting whatever kind the rule chain matched on the underlying ref. Nothing in the server ever wrote `EditionKind.alternate`, so every system-created alternate sat at `draft`; an alternate built from a version tag would have derived `release` and been retroactively promoted by the kind heal — a long CDN cache profile, the Releases bucket on the dashboard, and permanent exemption from lifecycle reaping for a preview deployment. Existing alternates converge to `alternate` on the next tracked build.
- The kind-convergence write in both heal paths now holds the edition's `EDITION_UPDATE` advisory lock, matching the edition-pointer write and keeper-sync's aggregate path. `publish_edition` reads `edition.kind` to choose the CDN cache profile, so a job that loaded the edition before an unlocked promotion committed wrote the KV pointer with the stale `short` profile and skipped the hostname purge, leaving the edge serving `max-age=60` for a `release` row.
