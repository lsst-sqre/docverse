### New features

- The object store gained `delete_prefix(prefix=...)`, which removes every object under a key prefix and returns how many it removed. It is the sanctioned way to reclaim a build tree: the S3 implementation pages `list_objects_v2` and issues `DeleteObjects` in the API's maximum 1000-key batches, filling each batch from the key stream rather than per list page, so a several-thousand-file build costs a handful of requests instead of one per file. A batch whose response reports a per-key failure raises `ObjectStoreError` rather than returning a short count, so the `purgatory_cleanup` sweep that calls it can never stamp a build as reclaimed over objects that are still on the store. A prefix holding nothing returns 0 without issuing a delete, which is the ordinary path for a build whose staging tarball was already dropped at completion.
- `ObjectStoreError` joins the `DocverseSlackException` family. Its message names the bucket, prefix, operation, the number of keys that failed, and up to ten of them with their S3 error codes — enough to tell one denied prefix from an expired credential without leaving Sentry, and bounded so a whole failed batch cannot blow up the issue title or the failing job's error record.

### Other changes

- `delete_prefix` refuses a blank prefix with a `ValueError` in both implementations rather than matching every key in the bucket. The prefix comes from `builds.storage_prefix`, and a row that lost its prefix is a bug upstream of the delete, not a licence to empty a bucket shared by every organization on it.
