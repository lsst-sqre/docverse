### Bug fixes

- An LTD rebuild of an edition a lifecycle rule tombstoned now brings its project in for the sync that judges the tombstone again, without waiting for some other edition of the project to change (PRD #830).
  - `keeper_sync_tier_other` keeps `lifecycle_preemptive` and `lifecycle_delete` edition state rows in its staleness check. Such a row ages from its `date_last_synced` or, when keeper-sync never synced the edition, its `date_tombstoned`, so a project whose only non-`main` editions are lifecycle-tombstoned is re-synced at its ordinary `tier_other` cadence, and a tombstone the sync judged and kept (which stamps `date_last_synced`) is left alone for the refresh threshold like any synced edition. `manual_delete` rows are still left out. On the first ticks after deploy, every project with a lifecycle-tombstoned edition becomes stale once, metered by the existing tier-cron enqueue budget; each such sync judges again only the editions LTD actually rebuilt.
  - The push hot path's check of a pushed ref in `keeper_sync_tier_main` now finds a lifecycle-tombstoned edition tracking the ref: an edition a lifecycle rule soft-deleted (`delete_reason` `lifecycle_delete`, or none on record) and its tombstoned state row, and, for an edition vetoed at import (`lifecycle_preemptive`), the tombstone among the project's listed LTD editions on the slug LTD gives the ref's edition, confirmed against the edition's `tracked_refs`. LTD's rebuild is compared with the row's `date_rebuilt_seen`, falling back to `date_tombstoned`, so a rebuilt edition reads `rebuilt` and enqueues the project's sync, and one LTD has not rebuilt since reads `unchanged`. `manual_delete` editions are still not looked at.
